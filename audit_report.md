# The "No Stone Unturned" Audit Report

Per your mandate, here is the ruthless, uncompromising audit of the DRMS codebase. This report identifies every instance of technical debt, architectural regression, and security vulnerability found within the core modules analyzed.

| Target Module/File & Line # | Category | Granular Issue Description | FAANG Refactoring Directive |
| :--- | :--- | :--- | :--- |
| `backend/src/controllers/authController.js` (Line 28-40) | Micro-Architecture / Clean Code | **Business Logic Bleed**: Request payload extraction and manual validation (e.g. regex tests) are performed directly inside the controller. This violates the Single Responsibility Principle and litters the controller with validation boilerplate. | Use Zod/Joi middleware: <br> `const RegisterSchema = z.object({ email: z.string().email(), password: z.string().regex(/^(?=.*\d)(?=.*[!@#$%^&*()_+\-=[\]{};':"\\|,.<>/?]).{8,}$/) });` |
| `backend/src/controllers/authController.js` (Line 80, 107) | Resiliency / Race Conditions | **Transaction Boundary Missing**: The `/register` flow performs multiple sequential reads and writes (`SELECT` to check existing, `INSERT` to users, `DELETE` and `INSERT` to OTP). If two concurrent requests hit with the same email, it can trigger race conditions or unique constraint violations without atomic guarantees. | Wrap the entire user creation & OTP generation block in a serializable transaction: <br> `await client.query("BEGIN TRANSACTION ISOLATION LEVEL SERIALIZABLE"); ... await client.query("COMMIT");` |
| `backend/src/controllers/authController.js` (Line 757-785) | Critical Security | **Missing Payload Sanitization**: The `updateProfile` function directly destructures `req.body` and merges it into a JSONB `profile_details` field. This lacks strict typing and sanitization, opening the door for prototype pollution or malicious payload injection into the JSONB column. | Apply strict object stripping before merging: <br> `const safeUpdates = z.object({ full_name: z.string().optional() }).parse(req.body);` |
| `backend/src/controllers/facultyParticipationController.js` (Line 75-82) | Edge-Case Error Handling | **Orphaned File Artifacts**: The file metadata is inserted into `project_files` inside a DB transaction, and the actual file is written to the disk via multer beforehand. If the `faculty_participations` insert (Line 86) fails, the DB transaction rolls back, but the physical file remains on the disk forever, causing a memory/storage leak over time. | Implement rollback cleanup in the `catch` block: <br> `catch (err) { await client.query("ROLLBACK"); if (req.file) fs.unlink(req.file.path).catch(console.error); throw err; }` |
| `backend/src/controllers/facultyParticipationController.js` (Line 362-435) | Micro-Architecture / Maintainability | **Brittle Dynamic SQL Construction**: The `listFacultyParticipations` controller relies on extensive manual string concatenation and array pushing (`params.push(searchTerm); conditions.push(...)`) to build complex search/filter queries. This is highly prone to off-by-one errors and makes unit testing SQL generation impossible. | Integrate a query builder (e.g. Knex.js) or Prisma for dynamic SQL: <br> `const query = knex('faculty_participations').where(builder => { if (searchTerm) builder.whereILike('faculty_name', \`%\${searchTerm}%\`) });` |
| `backend/src/config/db.js` (Line 42-66) | Resiliency / Configuration | **Weak Environment Validation**: The database connection pool blindly accepts `process.env` values. If a critical variable (e.g., `DB_USER` or `DB_NAME`) is missing, the application will boot successfully but immediately crash on the first DB query with cryptic `pg` connection errors. | Validate environment variables at boot time: <br> `const EnvSchema = z.object({ DB_USER: z.string(), DB_PASS: z.string() }); const env = EnvSchema.parse(process.env);` |
| `backend/src/config/db.js` (Line 104-126) | Edge-Case Error Handling | **Silent Pool Degradation**: The `pool.on("error")` handler logs errors but does not proactively attempt to drain or recreate the pool when it encounters fatal network partitions (`ECONNREFUSED`, `ECONNRESET`), potentially leading to zombie connections blocking the Event Loop. | Implement self-healing pool logic: <br> `if (criticalErrors.includes(err.code)) { logger.error("DB Pool fatally compromised. Triggering graceful shutdown."); process.kill(process.pid, 'SIGTERM'); }` |
| `backend/src/server.js` (Line 148-181) | Critical Security | **Missing Rate Limiting on Authenticated File Access**: The `/api/files/:filename` route verifies JWTs but lacks any rate limiting. A malicious actor with a valid student token could write a script to rapidly request files, causing IO exhaustion (Denial of Service) on the filesystem. | Implement explicit rate limiting for file downloads: <br> `const fileLimiter = rateLimit({ windowMs: 15 * 60 * 1000, max: 100, message: "Too many file requests" }); app.use("/api/files", fileLimiter);` |
| `frontend/src/api/axiosClient.js` (Line 34-95) | Resiliency / Network Reliability | **Lack of Exponential Backoff**: The custom `ApiClient` implementation throws network errors immediately on failure. FAANG-grade frontends must seamlessly absorb transient micro-outages (e.g., 502 Bad Gateway during deploys) via automatic retries with exponential backoff and jitter. | Wrap the `fetch` call in a retry utility: <br> `import pRetry from 'p-retry'; const response = await pRetry(() => fetch(url, config), { retries: 3, onFailedAttempt: error => { console.warn('Retrying...', error); } });` |
| `frontend/src/api/axiosClient.js` (Line 47-56) | Edge-Case / State Management | **Abrupt Token Expiration Handling**: When a 401 Unauthorized is caught, the client aggressively purges `localStorage` and forces a hard `window.location.href = "/login"` redirect. This immediately destroys any unsaved form data the user was working on (e.g., a massive Faculty Participation form). | Implement silent token refresh logic or a modal warning: <br> `// If 401, trigger a global Redux/Context action 'SESSION_EXPIRED' to show a modal preserving form state, rather than a hard redirect.` |
